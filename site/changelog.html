Unreleased

Compare on GitHub

Fixed

  • Errors are worded for people. Connection refused (os error 111), failed to lookup address information, password authentication failed, No such file or directory (os error 2) and the temporary .part name no longer reach the screen: a connection says "Nothing is listening on 127.0.0.1:5999. Is the server running, and is the port right?", "The host db.internal could not be found. Check the name or your VPN." or "The server rejected the password for user postgres."; a file says "The file /x/y.csv does not exist." or "The folder /nonexistent/dir does not exist.". One mapping (theta_core::friendly) serves Test Connection, the explorer, toasts, Import, Export, Export Database, Run SQL Script, Open and Save, theme import and --script; Test Connection keeps the driver's own text on a "Details" line.
  • A connection failure no longer says "could not connect" twice, and a failed Modify Table apply is shown in the editor only (a toast appears when another tab is in front); Import no longer prints the failing row in the report and again in the footer.
  • Copy Table checks the new name against the live catalogue while you type (a table copied a moment ago counts) and disables Copy with the reason. The clean-up sentence after a failed copy is true in every case: made and rolled back, refused before anything was made (an existing table is untouched), or left behind.
  • Terminate Session and Cancel Query confirmations read once ("Terminate session 12756 (user postgres, database quarry_demo)?") and the badge agrees with the text ("Theta's own connection" or "Affects another session"). Truncate and Drop say what they delete, give the catalogue's row estimate and say when it cannot be undone.
  • Start-up problems (bad --connect URL, missing --script file, unknown --theme, a broken theme file or templates.json, a --modify table that is not there) are shown in the window and recorded in Messages as well as printed to stderr. Toasts now appear one at a time instead of piling up behind each other, so a warning is no longer covered by "Connected to …".
  • Importing an empty file says "The file is empty." and a header-only file says it has a header but no rows; Import is off, except into a new table, where the button reads Create Table and the footer says the empty table was created.
  • Counts, durations and rates read the same everywhere ("1 row", "831 ms", "1.24 s", "6 rows/s"); "1 ragged rows" and similar are fixed.
  • Error lines in Messages read the same for every engine: "SQLSTATE 42P01" or "Error 1305 · SQLSTATE 42000", with the server's DETAIL and HINT labelled.
  • Edit Live Templates, Zed theme import and a broken templates.json say what happened and name the file. Editor hints are in British spelling ("centre cursor"). The migration script no longer has a lone -- ; after commented statements, and the Compare header says "held back" once.
  • Copy Table opened from the palette had no focus, so esc and tab acted on the editor behind it; its name field is focused now.
  • ctrl-alt-enter (Run on Several Connections) was swallowed by the editor in the Standard and Helix key maps, and with fewer than two connections it crashed the app instead of saying so.
  • The "query is already running" message named ctrl-., which is Quick Fixes in the editor. Cancel is shift-F5 in every key map (it replaces mod-.), and the message reads the key from the bindings.
  • The Chart tab trapped the keyboard when the result had no rows or nothing to plot: ctrl-1, ctrl-2 and esc now work, and a second esc returns to the editor.
  • The History tab is usable from the keyboard (mod-shift-h, arrows, enter loads the statement into the editor, / searches, esc leaves) and says "1 row".
  • Focusing the results (ctrl-2, space g) makes the first cell (or the one that was current) active, so the first key moves from it instead of being swallowed.
  • The New Connection dialog opens with the URL field focused, enter anywhere saves and connects or says what is missing, an empty user is flagged like an empty host, the hints are the selected product's and marked "e.g.", and a missing password is reported once, in words.
  • Confirmation dialogs (Apply Changes, Truncate, Drop, Terminate Session, delete rows, drop role, delete connection or folder) press the focused button on enter, show which button is focused and say how to move; destructive ones open with Cancel focused.
  • Run SQL Script runs on enter in the file field, and says when there is no file.
  • The gear and application menus show the whole Ctrl+K Ctrl+T chord for Select Theme.
  • The Standard key map has find and replace: ctrl-h (or ctrl-h inside the find prompt), enter replaces one and moves on, ctrl-enter replaces all.
  • Reopen Closed Tab says why there is nothing to reopen after an empty console was closed, and the docs say empty consoles are not kept.
  • Sorting or filtering a result that was cut off at the row limit said nothing and showed wrong maxima and "No rows". The footer now says "Sorted within the 1,000 rows loaded" for as long as it applies, and Load all (ctrl-shift-l, or the palette) fetches the rest with progress and cancel, up to 500,000 rows, keeping the sort and filter.
  • A row added in the grid came back with NULL for its generated key. After Submit the grid shows what the database stored (keys, defaults, computed columns), read back with RETURNING, LAST_INSERT_ID() or a reload.
  • After a rollback or a failed commit, grids that may show rows that were never stored are marked "Rolled back: these rows may no longer exist" with a one-key Refresh (F5).
  • Floats print as the shortest text that reads back as the same number, with an exponent below 1e-5 and from 1e16 (1.5e300, not 300 digits), and a whole float keeps its .0 so 1.0 is not mistaken for the integer 1. Copy and export write the same text.
  • Polygons were drawn as faint 2 px squares that vanished against the basemap at world zoom; collapsed polygons are now outlined markers no smaller than a point, in dark and light.
  • The squiggle under a server error started one character early (the position is a byte offset, not a 1-based character position), which put a stray tick at the end of the previous line for errors after a line break.
  • The same error was listed twice in Problems and without a column: the server's message now replaces ours at its position, and Problems shows "line:column".
  • A script that stops at its first error ends its Messages entry with "Stopped at statement 3 of 7: 4 statements were not run", and the status bar shows the failure instead of the previous statement's row count.
  • A read-only connection is marked in the title-bar connection switcher, the status bar and the explorer row, not only after a write is refused.
  • A failed Submit in the grid was shown three times (footer, toast and Messages) without saying which row; it is now shown once in the footer, with the row (id = 2, new row 1), the cursor moves to it and the staged edits are kept.

Changed

  • Confirmation buttons are Title Case ("Apply 2 Changes").
  • Cancel Query is shift-F5 instead of mod-..
  • The grid footer has Load all and Refresh; F5 in the grid refreshes the result.

0.1.0-alpha.9

2026-11-12Compare on GitHub

Added

  • Data compare (mod-alt-x, space X, :datacompare, explorer menu on a table, palette): compare the rows of two tables that share a key, on one connection or two, across PostgreSQL, MySQL and MariaDB and SQLite. The dialog picks both tables and the key (the primary key, a unique constraint of the source, or columns you tick); columns are matched by name ignoring case and the ones only one side has are listed and ignored; a table with no usable key is refused with the reason. theta_sql::data_diff merges two key-ordered streams into only-in-source, only-in-target, different (with the differing columns) and same, in memory bounded by two pages and the first 10,000 differences (the counts stay exact, and the tab says when it capped). Values are compared by documented rules (1 and true, numeric scale, timestamp precision and zone, NULL against NULL, JSON structurally). The key order is verified on the client; a stream that is out of order (PostgreSQL or MariaDB sorting text by collation) makes the runner (theta_import::compare) read again in binary collation, and an order that still disagrees, a duplicate or a NULL key is refused with a sentence. Runs on sessions of its own with progress and cancel (esc). Open Sync Script in Console opens INSERT/UPDATE/DELETE statements that make the target equal the source in a console on the target (deletes commented out unless d includes them). An in-memory SQLite or a DuckDB database cannot be compared (it cannot be opened a second time). Live tests cover PostgreSQL to PostgreSQL, PostgreSQL to MariaDB and back, and SQLite to SQLite, including a composite key, text keys whose orders differ, cap, cancel and the round trip (apply the script, compare again, no difference).
  • Schema compare (mod-alt-s, space S, :schemacompare, explorer menu on a schema, palette): a dialog picks a connection and schema for the source and the target (everything by keyboard), and a result tab shows a tree of differences with the chosen one side by side. The pure comparison is theta_sql::schema_diff: tables, columns (type, nullability, default, identity, generated expression, comment), primary keys, unique constraints, foreign keys (columns, target, actions, deferrability), indexes, checks, table comments, MySQL table options and the definition text of views; routines by signature only. What the catalog does not carry (triggers, routine bodies, sequences, collations, privileges, partitioning, custom types, column order) is not compared, and the tab says so. For two schemas of the same product Open Migration Script in Console opens a console bound to the target with the script, ordered by dependency (views and foreign keys off, tables dropped, created, altered, foreign keys on, views back), through the DDL engine, so SQLite gets its documented table rebuild. Destructive statements (drop table or column, narrowing types, dropped or changed constraints and indexes) are commented out with a -- destructive: marker unless the d toggle includes them; held back, they still leave a script that is correct in order. Across two products only the differences are shown, with the reason. Live tests on PostgreSQL, MariaDB and SQLite apply the script to copies of the target and compare again.
  • ER diagram (mod-alt-g, space G, :diagram [schema | table], explorer menu on a schema and on a table, palette): a tab that draws a schema, or one table and the tables it references or that reference it, as boxes with columns, types and PK / FK markers and foreign keys as orthogonal edges that end at the right columns (a composite key ends at a bracket spanning its columns; a nullable key is dashed). The layout is the new pure crate theta-diagram: layered, deterministic, with cycle breaking, self-references, slots that keep long edges clear of other tables and a measured 100+ tables in well under a second. Pan with drag, scroll or hjkl / arrows, zoom with + - 0 and ctrl-scroll, f fits, tab / shift-tab select, / jumps by fuzzy name, enter opens the table's rows, the selection's edges and neighbours are highlighted. s writes an SVG (own serializer, no dependency), m copies Mermaid erDiagram text. There is no PNG export (GPUI can capture an image only in its test builds).
  • Run on Several Connections (mod-alt-enter, space m, :multirun): run the current statement or script on each chosen connection concurrently. Each keeps its read-only setting and its transaction mode; a failure, refusal or busy connection is reported for that connection only. The result is a Summary tab (statements, rows, time and status per connection) and one tab per connection that returned rows.
  • Local history for consoles (mod-alt-h, space h, :lhistory): every console's text is snapshotted when a statement runs and after a pause in typing, stored under the config folder with per-console and total size caps and pruning, written atomically so a killed process loses nothing it had saved. A dialog lists the snapshots with time, kind, first line and a line count against the editor, shows a diff (theta_editor::diff::line_diff) and restores a snapshot as one undoable edit.
  • Copy Table to… (explorer menu, palette, :table copy): copy a table, with or without its rows, to another schema or to another open connection, including across products (PostgreSQL, MySQL and MariaDB, SQLite, DuckDB). The column types go through an explicit mapping table; the dialog shows the CREATE TABLE and every column whose type had to be substituted, with the reason, before anything runs. Rows are streamed in pages inside one transaction (a dropped table where the target cannot roll back DDL, as in MySQL), with progress, cancel and a report of what was cleaned up. Feature::CopyTable turns it off for SQL Server and ClickHouse.
  • Charts: a Chart tab next to Results (mod-shift-g, space C, :chart). Bar, line, area, scatter and pie charts of the active result; X, one or more Y columns, an optional series column and an aggregate (sum, average, count, min, max) for Y where X repeats; defaults chosen from the column types so a two-column result charts at once; ticks, legend, hover readout and keyboard control; painted with GPUI's own primitives in the theme's colours. The data shaping is the new pure crate theta-chart. There is no PNG export (GPUI can capture an image only in its test builds).
  • Search Across Tables (mod-alt-f, space s, :grep, explorer menu): find a text in every table of a connection, a schema or a hand-picked list. One generated, fully escaped query per table (PostgreSQL, MySQL and MariaDB, SQLite, DuckDB), run on up to four sessions with a row limit and a timeout per table; hits stream into a list grouped by table and column, and Enter opens the table filtered to the matching rows. Skipped, timed-out and failed tables are listed with the reason. SQL Server and ClickHouse are off through Feature::TableSearch, with the reason shown.
  • Cell viewer (the grid's inspector, extended): images (PNG, JPEG, GIF, WebP, recognised from their magic bytes) are drawn; JSON can be folded ([ / ], header buttons, chevrons); binary is a hex dump of up to 64 KiB with the real length; every truncation says how large the value really is. Toggle Cell Viewer and Copy Cell Value are in the command palette, bound to mod-shift-v and mod-shift-y, space v / space V in Helix and Vim, and :cell / :cell copy.

0.1.0-alpha.8

2026-11-12Compare on GitHub

Added

  • A real SQL parser (theta_sql::syntax): hand-written, error-tolerant recursive descent over the existing lexer for PostgreSQL, MySQL, SQLite, DuckDB, T-SQL and ClickHouse. The tree is lossless (every node has a byte span; trivia is kept). Queries and DML are parsed in depth, DDL and the rest shallowly. It reports an error only where the text is invalid in every dialect the rule applies to.
  • Name resolution (theta_sql::analysis) against the catalog: aliases, CTEs, derived tables, USING / NATURAL, * expansion, correlated and LATERAL scopes, RETURNING, with dialect case folding and quoting. When it cannot tell, it says nothing.
  • Diagnostics from the tree: syntax errors with exact spans, unknown table / column (naming the tables searched), ambiguous column, undefined / duplicate alias, column-count mismatch, ungrouped column. Inline, with a new Problems tab (ctrl-shift-m) that jumps to the problem; F8 / shift-F8 step through them. Computed after a pause, off the UI thread.
  • Quick fixes and refactorings (ctrl-., Helix/Vim space a): did you mean, qualify an ambiguous column, expand *, add alias and qualify, add GROUP BY columns, comma join to JOIN, flip JOIN, extract / inline CTE, upper- / lower-case keywords.
  • Go to definition (F12, gd), find usages (shift-F12, gr) with a picker, occurrence highlighting, and rename (F2, Helix/Vim space n) for aliases, CTEs and CTE / select-alias columns as one undo step, refusing collisions and capture with the reason. Catalog renames are not offered.
  • A differential test against PostgreSQL 16, MariaDB 10.11, SQLite and DuckDB with a corpus of about 2,000 statements per dialect (T-SQL and ClickHouse: documentation examples), and parser robustness tests (truncation at every token, random deletions, token soup, deep nesting, linear time).

Changed

  • The linter's token-based syntax and name checks were replaced by the tree-based ones; the remaining meaning-level checks (UPDATE / DELETE without WHERE, = NULL, implicit cross join) are kept.
  • Four more common typos are now flagged in PostgreSQL, MySQL/MariaDB, SQLite and DuckDB: ORDER / GROUP without BY, UPDATE ... SET col 'x' without =, a missing comma before a function call in the select list (select a count(*)), and a CASE that is never closed; CASE without END is flagged in every dialect.
  • The backtick is an operator, not a quote, in PostgreSQL (it is still a quote in every other dialect).

0.1.0-alpha.7

2026-11-11Compare on GitHub

Fixed

  • A console run (or --run) that contained DDL left the explorer showing the old schema on every product. The catalog is now refreshed once after such a run.
  • CREATE SPATIAL INDEX / FULLTEXT on MySQL and MariaDB: the DDL engine wrote USING SPATIAL, a syntax error (found by the dump round trip). DuckDB views are dumped from the whole CREATE VIEW its catalog stores.

Added

  • Server administration: three tools, each reachable from the explorer's connection menu, the command palette and a : command, and keyboard-driven in the Helix, Vim and Standard key maps (see the user guide chapter Administer a server). Products that cannot do one say why, from the same capability table as everything else (Feature::Sessions, Roles, RoleEdit, Dump).
    • Sessions tab (:sessions): a live table of server sessions with a filter, sorting, a refresh interval and a pause toggle; sessions that are blocked are highlighted with the session that blocks them, and Cancel Query and Terminate Session confirm with the exact SQL first. PostgreSQL (and TimescaleDB), MySQL / MariaDB, SQL Server and ClickHouse. The tab uses a session of its own, so it keeps working while a console is busy, and it marks Theta's own sessions. Verified live on PostgreSQL 16, MariaDB 10.11 and ClickHouse 18.16.
    • Roles tab (:roles): roles and users with their attributes, memberships and privileges grouped by object; create, alter, set password, add to / remove from a role, grant, revoke and drop, each as a form with a live preview and a confirmation. The password is never written to Messages, history or any file (shown as '***'), and server errors that echo the statement are cleaned before they are logged. PostgreSQL and MySQL / MariaDB edit; SQL Server lists logins and server roles read-only (unverified).
    • Export Database… (:dump) and Run SQL Script… (:script FILE). The dump is Theta's own, streaming and cancellable: DDL from the DDL engine in dependency order (foreign keys after the data on PostgreSQL and MySQL), data as multi-row INSERTs, sequences and identity counters, views. The dialog lists what it does not capture, and offers pg_dump / mysqldump when installed with the exact command (password in the environment, never in the arguments). Run SQL Script splits the file as it reads it (never loaded whole), stops at the first error or collects them, can run in one transaction, and cancels. Round trips of the demo data are tested on PostgreSQL, MariaDB, SQLite and DuckDB.
    • theta_sql::admin holds the per-product SQL and row mapping, theta_import::dump, script and native the pipelines.
  • New Table suggests foreign keys before the table exists: inference runs on the draft (theta_sql::infer_foreign_keys_for), with the same heuristics as the catalog-wide inference.
  • Eight more databases. CockroachDB, Amazon Redshift, TimescaleDB, YugabyteDB and TiDB (they reuse the PostgreSQL and MySQL drivers, each with its own descriptor, URL schemes, icon and the handling its documentation calls for), plus DuckDB, SQL Server and ClickHouse with drivers of their own.
    • DatabaseKind gained family() (the SQL dialect), unsupported(Feature) (a stated reason for what a product cannot do; menus, palette, --modify, the grid and Explain show it instead of sending failing SQL) and detect() / mismatch(), which compare version() with the chosen product on connect and warn once.
    • CockroachDB: text-plan EXPLAIN (with ANALYZE) parser, routines from information_schema. Redshift: introspection from information_schema, SVV_TABLE_INFO and pg_constraint, plain-text EXPLAIN, no ANALYZE, import and table editor disabled with reasons. TimescaleDB: hypertables listed, internal schemas hidden. YugabyteDB: EXPLAIN without BUFFERS. TiDB: tabular EXPLAIN parser, KILL QUERY.
    • DuckDB: file or :memory:, introspection through the duckdb_*() functions, EXPLAIN / EXPLAIN ANALYZE as a plan, cancel through the interrupt handle, DECIMAL, HUGEINT, temporal types and LIST / STRUCT / MAP (as JSON) values, Parquet and CSV through plain SQL; extensions are never downloaded. Behind the default-on cargo feature duckdb because it adds about 55 MB to the binary and about 15 minutes to a clean build.
    • SQL Server (TDS via tiberius with rustls): SQL authentication, Encrypt off / on / trust certificate, sys.* introspection (identity and computed columns, keys, checks, indexes, routines), SET ROWCOUNT row limit, cancel by KILL, showplan XML for EXPLAIN (estimated) and STATISTICS XML (actual), geometry / geography as EWKB, [bracket] quoting, TOP, GO batches and T-SQL keywords. The live test passes in CI against SQL Server 2022; the app has not been driven by hand against one.
    • ClickHouse over HTTP: engine, sorting key, primary key and partition key in the explorer (Storage), KILL QUERY cancel, EXPLAIN json = 1, Nullable / Array / Map / Tuple / LowCardinality / DateTime64 / Decimal / UUID / IPv4 / IPv6 values, backtick quoting, ClickHouse functions; the grid is read-only with the reason shown.
    • The explorer shows a table's storage facts (engine, distribution style, hypertable) in a Storage section; SQL Server's TOP in generated SELECTs; the connection dialog words TLS per product and follows ClickHouse's HTTPS port; --connect and the URL field take cockroachdb://, redshift://, timescaledb://, yugabytedb://, tidb://, duckdb://, sqlserver:// (encrypt, trustServerCertificate), clickhouse:// and clickhouses://.
    • docs/ARCHITECTURE.md has a walkthrough of how to add a database kind; the README lists, per product, whether it has been run against a real server.

Changed

  • New app icon and logo: the theta is now the lowercase theta of the GFS Didot typeface (a tall, high-contrast serif oval with a thin crossbar joined to both sides), white on the same dark tile. Its outline is embedded in packaging/icons/gen_icon.py, the single source of the icon, and GFS Didot's licence (SIL OFL 1.1) is credited in docs/THIRD_PARTY.md, the NOTICE file and the website footer. The icon has separate, heavier drawings of the same letter for 16, 24 and 32/48 px, so it stays legible in a taskbar; the in-app mark and the website use the same design.
  • The statement splitter, formatter and parameter finder know T-SQL's GO, BEGIN TRANSACTION and DECLARE; the formatter keeps GO on its own line.

0.1.0-alpha.6

2026-11-11Compare on GitHub

Added

  • Modify Table / New Table editor. A workspace tab with a header (table name, connection, database kind, a summary such as 3 statements · 1 destructive, Revert, Copy SQL, Open in Console, Execute), the sections Columns · Keys · Foreign Keys · Indexes · Checks · Options (counts and error / warning dots) and a persistent DDL Preview (beside the grid, below it in a narrow window, resizable, collapsible): one block per statement with badges (destructive, table rewrite, lock, implicit commit, outside transaction, rebuild), the engine's explanation, SQL highlighting and a copy button, validation problems with Fix buttons, and a "No changes" state. Columns is a virtualised, typed, keyboard-driven grid: name, type (dialect-aware suggestions, free text allowed), nullable, default, primary key (with its position), identity / auto-increment, comment; a removed column stays, struck through, until Execute. Keys edits the primary and unique keys, Foreign Keys picks the referenced table from the catalog and offers the inferred keys with one click, Indexes edit columns in order, unique, method and a partial predicate, Checks and the table comment are editable, and the MySQL engine / charset / collation are shown. Undo and redo within the tab. Execute confirms the exact SQL with its badges and runs it through the same path as the explorer's table actions: one transaction on PostgreSQL and SQLite (SQLite's rebuild keeps its pragmas outside it and checks foreign keys before committing; the preview shows which statement is running), statement by statement on MySQL / MariaDB (stated, and a failure names what was already applied), inside the open transaction in manual mode, refused on read-only connections. On failure the failing statement is marked with the server's error and every edit is kept; on success the tab reloads as Modify <name> and the table is selected in the explorer. Closing a tab with unapplied changes asks. Entry points: New Table… (Tables group, palette, :table new [SCHEMA], theta --new-table [SCHEMA]), Modify Table… (table menu, palette, :table modify NAME, theta --modify TABLE), Modify Column…, Rename Column…, Drop Column…, New Index…, Drop Index…, New Foreign Key…, Drop Foreign Key… and Add as Foreign Key… on a suggested key. Fully keyboard operable in the Helix, Vim and Standard key maps (see KEYBINDINGS); no new global chord (Execute is mod-enter).
  • DDL engine additions (theta_sql::ddl): per-dialect type, index-method, foreign-key-action and identity vocabulary; plan_script (how a script is wrapped and run); validation issues carry their section; check_names (table, constraint and index name clashes) and check_changes (MySQL refuses to change the type of a column that a foreign key uses, on either side).
  • Import Data (CSV / TSV). Import Data… on a table, Import as New Table… on the Tables group, the palette (Import Data from CSV/TSV…, Import CSV/TSV as New Table…), :import [FILE] in Helix and Vim, and theta --import FILE [--into [SCHEMA.]TABLE]. The dialog has a typed path field (Browse… is optional), a detected format (delimiter, quote, encoding, header row; each can be overridden), a live preview of the first 100 rows, a Columns tab that maps file columns onto an existing table (auto-mapped by normalised name, per column skip, target type shown, mismatches flagged) or lays out a new table (editable names and types with the generated CREATE TABLE shown), and options (empty fields are NULL, a NULL token, skip bad rows instead of stopping, empty the table first, rows per INSERT). Validate parses the whole file off the UI thread and lists every problem with its line and column without writing anything; Import shows a progress bar with rows read / inserted / skipped and rows per second, and Cancel rolls everything back. An import is one transaction (in a manual-commit session it joins the open transaction through a savepoint and leaves it open), each batch runs in a savepoint so a rejected row is named exactly (or skipped and listed), statements are kept under 1 MB and under half of MySQL's max_allowed_packet, and a table created by a failed import is gone again. Emptying the table first shows the exact statement and asks twice.
  • Export Data. Export Data… on a table and Export Table Data… in the palette (:export [TABLE]) write a whole table as CSV, TSV, JSON or SQL INSERTs, paged by primary key (constant memory, stable while the table changes; OFFSET paging without one), with progress and Cancel. A cancelled or failed export leaves no file.
  • Table actions. Rename…, Duplicate Structure…, Truncate… and Drop… on a table (and in the palette). Each shows the exact SQL and the engine's warnings in a confirmation dialog; Drop lists the foreign keys that reference the table; read-only connections refuse; a manual-commit session runs the statement inside its open transaction; MySQL's implicit commit is stated plainly.
  • DDL engine (theta_sql::ddl): TableDraft (columns, primary key, unique constraints, foreign keys, indexes, checks, comments, identity and generated columns) built from the catalog, create_table, and an id-based diff that produces the ordered, minimal ALTER script per dialect with each statement tagged (destructive, table rewrite, implicit commit, lock, outside a transaction) and explained. Renames are renames, never drop-and-add. SQLite changes that ALTER TABLE cannot do use the documented table rebuild. Includes validation (duplicate names, missing types, primary key on a nullable column with an auto-fix, foreign-key type checks).
  • Catalog: identity / auto-increment and generated columns, check constraints, unique constraints (distinct from unique indexes), partial and expression indexes, deferrable foreign keys, view definitions and MySQL table options, for PostgreSQL, MySQL / MariaDB and SQLite.
  • New crate theta-import: streaming RFC 4180 parser (quoted newlines, configurable delimiter, quote and escape, ragged rows, huge fields, BOM, UTF-8 / UTF-16 / Latin-1), format sniffing, type inference, typed conversion with row / column / reason errors, and the import and export pipelines. Measured on 1M rows (77 MB, 5 columns, dev profile): raw parse 4.5M rows/s, parse and convert 1.1M rows/s, end to end 69k rows/s into PostgreSQL, 104k into MariaDB and 232k into SQLite.

All new fields are serde-default. No Connection / Driver trait change.

0.1.0-alpha.4

2026-11-11Compare on GitHub

Renamed from Quarry to Theta

The project is now Theta and its icon is the Greek letter θ. The name comes from the theta join (θ-join) of relational algebra, the general form of JOIN. Entries below this one keep the name that was current when they were written. The GitHub repository keeps its old address (JesseWilliamson/Quarry) for now; GitHub redirects it once it is renamed.

Your data carries over:

  • Configuration, history, consoles and the demo database move from <config dir>/quarry/ to <config dir>/theta/ the first time Theta starts, if the new directory does not exist yet (renamed in place, copied if the two are on different filesystems; a notice is printed to stderr). Nothing is overwritten and nothing moves while THETA_CONFIG_DIR is set. The map tile cache moves from <cache dir>/quarry/ to <cache dir>/theta/ the same way.
  • Themes: "Theta Dark" and "Theta Light" are now Theta Dark and Theta Light; a settings.json that names the old ones is read as the new ones, silently (the file is rewritten with the new names the next time settings are saved). The bundled theme file quarry.json is now theta.json.
  • Saved passwords: the keychain service is now theta. A password stored under the old quarry service is read as a fallback and copied to the new one the first time it is needed; the old entry is left in place until the connection is deleted.

What you have to change by hand:

  • Binary and package: quarry is now theta (cargo run -p theta, theta --demo, theta --version prints theta 0.1.0-alpha.4); library crates are theta-core, theta-drivers, theta-sql, theta-geo, theta-editor, theta-editor-view, theta-grid, theta-map-view, theta-plan-view and theta-ui.
  • Environment variables: every QUARRY_* variable is now THETA_* (THETA_CONFIG_DIR, THETA_CACHE_DIR, THETA_WINDOW_SIZE, THETA_DEMO, THETA_TILE_URL_OVERRIDE, and the test and debug switches). The old names are not read any more.
  • Release artifacts: theta-<version>-linux-x86_64.tar.gz, Theta-<version>-linux-x86_64.AppImage, Theta-<version>-macos-<arch>.zip (containing Theta.app) and theta-<version>-windows-x86_64.zip (theta.exe). The Linux install uses theta.desktop, the theta hicolor icon name and ~/.local/bin/theta; uninstall the old quarry files separately.
  • macOS bundle id: dev.quarry.Quarry is now dev.theta.Theta, so macOS treats it as a different app (its preferences and permissions do not carry over).
  • The map tile User-Agent is now Theta/<version> (+<repository url>); the demo stores are "Theta Coffee <City>" (--demo databases created earlier keep the old names).
  • The local test databases keep the legacy name quarry_demo (and the MariaDB user quarry): renaming a live test database would only add churn. Key contexts and element ids moved from Quarry… to Theta…, which matters only to custom keymaps written against the previous alpha.

Changed

  • App icon: the lowercase Greek letter theta, drawn as geometry (a ring with a horizontal bar that overshoots it a little) in thin white lines on the same dark grey gradient tile. The ring is 0.77 as wide as it is tall, the glyph is 54% of the tile height and the stroke 3% of it. The 32/48 px, 24 px and 16 px icons are separate drawings with every edge on a whole pixel (bar on a pixel row, counters at least 2 px at 16 px), and the in-app mark has a heavier stroke. theta-light.svg is the dark-on-light version; everything is regenerated by packaging/icons/build.sh, which now also writes theta-24.svg.

0.1.0-alpha.1

2026-11-11Compare on GitHub

The first release. It is an alpha: the application is complete and wired together, and was run by hand on Linux (X11) against PostgreSQL 16 with PostGIS, MariaDB 10.11 and SQLite. The macOS and Windows builds are compiled and unit-tested in CI but have not been exercised by hand. See Known limitations in the README.

Added

Connections

  • PostgreSQL (PostGIS-aware), MySQL / MariaDB and SQLite connections with TLS modes Disable, Prefer, Require and Verify full.
  • SSH tunnels with key file (optional passphrase), password or ssh-agent authentication; host keys are checked against ~/.ssh/known_hosts (trust on first use, a changed key is refused).
  • Connection dialog with URL paste, Test Connection, Save and Save & Connect; read-only connections; an accent colour per connection; edit, duplicate and delete from the explorer.
  • Passwords in the operating-system keychain, never in connections.json; in memory only when there is no keychain.
  • Automatic reconnect when a statement fails because the session was lost (PostgreSQL class 08 and 57P01/57P02/57P03, MySQL "server has gone away" / "lost connection", broken pipe, EOF): the first failing statement reconnects at once and a plain query outside a transaction is re-run once; anything else is reported as not re-run.
  • Run and Explain on a console whose connection is down connect, wait and then run, and show the connection error in Messages when that fails.
  • Reopen Closed Tab (mod-shift-t, palette, :reopen): the last 20 closed consoles (text, connection, cursor) are kept across restarts, so closing a tab never discards work.
  • --help, --version; --ssh without --ssh-key authenticates with the ssh-agent; unknown flags print the usage and exit with status 2. --demo reuses an existing demo connection.
  • Panics are logged to <config dir>/logs/panic-*.log and shown as a notice with the log path.
  • Command-line flags: --demo, --connect URL (repeatable), --run SQL, --script FILE, --ssh user@host[:port] with --ssh-key PATH, --theme NAME, --stress-catalog[=N], --version, --help; QUARRY_DEMO=1.
  • A demo database (--demo): customers, orders, products, stores, delivery zones and routes in SQLite.

Key handling

  • While the SQL editor has focus its engine's keys win over application shortcuts, derived from the engine itself and tested for both key maps and every mode: Helix Insert ctrl-w deletes a word instead of closing the tab, ctrl-k kills to the end of the line, ctrl-b pages up, ctrl-o is the jumplist, ctrl-n / ctrl-p move the completion selection, and F5 runs all. Refresh Schema is F5 in the explorer and mod-alt-r everywhere. The editor publishes keymap, mode, prompt and completion as key context.
  • The results grid keeps its own chords (mod-0 set NULL, mod-enter, ...), the explorer and pickers keep ctrl-n / ctrl-p.
  • The editor scrolls horizontally to the caret after every edit, including typing at the end of a long line and text from the input method.
  • Messages hide a meaningless error code (SQLite's "Unknown"); Cancel Query, Commit Transaction and Roll Back Transaction are named the same in menus, palette, tooltips and docs.

Connection dialog

  • The database type is a dropdown (icon and label per type, keyboard navigable) driven by one descriptor per kind in quarry-core: label, icon, default port, URL schemes and which form sections apply. Adding a database kind needs no dialog change.

Map

  • Basemap registry and picker (toolbar menu, Settings › Map): OpenStreetMap Standard (default), OpenTopoMap, None (graticule) and user-defined basemaps with {s} and {r} support, per-basemap attribution, max zoom (overzoom beyond it), dark flag and tile cache. The old map_tile_url setting is migrated. CARTO basemaps are not built in: their 2026 terms require an API key (see the user guide).
  • A quieter scale bar (1px rule, end ticks, haloed label) in the bottom-right corner above the attribution.
  • Hover cards, the context menu and the layers popover, and the plan flame-graph card, are drawn on the window overlay layer and clamped to the window, so a short bottom panel no longer clips them. Focus rings of switches in the connection and settings dialogs are no longer cut off at the edge of the scroll area.

Explorer

  • Connections, schemas, tables, views, routines, sequences, columns, keys, foreign keys and indexes, with row estimates, a filter box and keyboard navigation.
  • Foreign keys inferred from column names, shown as Suggested with a confidence, and a Related Tables… picker that lists declared and suggested keys and opens a JOIN query.
  • Table context menu: Open Table, Copy Name, Copy Qualified Name, Generate SELECT / INSERT / UPDATE / DELETE, Show DDL.

Editor

  • A modal Helix key map (counts, registers, macros, text objects, surround, multiple selections, regex selections, : command line, a which-key box for the space menu) and a Standard key map with Zed's default bindings.
  • Context-aware completion for keywords, schemas, tables, columns, aliases, functions and snippets, with JOIN … ON … suggestions from declared and inferred foreign keys; auto-trigger after FROM, JOIN, ON, INTO, UPDATE, TABLE; Enter inserts a newline unless a suggestion was chosen.
  • SQL formatter (indent width and keyword case are settings) and a diagnostics pass for syntax problems, UPDATE/DELETE without WHERE and unknown names. A failed statement is underlined at the server's error position.
  • Hand-written SQL highlighter that copes with half-typed statements.
  • Tabbed consoles that persist across restarts (text, cursor, title, connection, tab order), drag to reorder, Open SQL File… and Save Console As….
  • Editor and results font zoom (mod-=, mod--, mod-0).

Running SQL

  • Run the statement under the cursor, the selection or the whole script; cancel a running query; one query at a time per connection; each result gets its own tab; a configurable row limit that stops the server.
  • Transactions: Begin Transaction, Commit Transaction and Roll Back Transaction, a TXN open indicator with Commit and Roll Back buttons, and a prompt when closing a console or quitting with a transaction open.
  • Confirmation before UPDATE / DELETE without WHERE and before Explain Analyze of a write.
  • Messages tab with per-statement outcomes, notices and errors (code, detail, hint); History tab with search, up to 5,000 entries.

Results

  • Virtualised results grid: type-aware sorting, filtering, rectangular selection, column resize and auto-fit, a value inspector, copy as TSV / JSON / INSERT.
  • Editable results: stage cell edits, new rows and deletions, review the generated UPDATE / INSERT / DELETE statements, and apply them in one transaction.
  • Export to CSV, TSV, JSON, Markdown or SQL INSERT statements for the whole result or the selection, to a file or the clipboard.
  • Foreign-key columns are marked and can be followed to the referenced row (ctrl-click).

Plans and map

  • Explain and Explain Analyze for PostgreSQL, MySQL/MariaDB and SQLite as a tree table, a flame graph and the raw output, with insights (sequential scans, bad row estimates, nested-loop rescans, spills, cartesian products, MySQL filesort and temporary tables, SQLite full scans) and suggested CREATE INDEX statements that open in a console.
  • Map for geometry columns (WKB, EWKB, WKT, GeoJSON; WGS 84, Web-Mercator, UTM) on an OpenStreetMap basemap with an on-disk tile cache, or on a planar grid; layers, feature picking, measure tool, copy coordinates, GeoJSON export, and selection shared with the grid.

Look and feel

  • 38 bundled themes (Theta Dark, Theta Light and 36 from 21 gpui-kit theme files), follow-the-system appearance, import of Zed theme files, IBM Plex Sans and Lilex fonts.
  • Command palette, table, connection and theme pickers, a settings dialog (Appearance, Editor, Data, Map, Keymap, About) and a tolerant hand-editable settings.json.

Libraries

  • quarry-core (the shared contract), quarry-drivers, quarry-sql, quarry-geo, quarry-editor as pure Rust crates; quarry-ui, quarry-editor-view, quarry-grid, quarry-plan-view and quarry-map-view as GPUI crates, each with a stand-alone demo.

Packaging and docs

  • Application icon; Linux tarball with install.sh and an AppImage; macOS .app bundle (ad-hoc signed, not notarised); Windows zip with an embedded icon (unsigned); SHA256SUMS; a release workflow that creates a draft GitHub release, with a dry-run mode.

  • README, user guide, key binding reference, architecture and development guides, contributing guide and a generated third-party licence list.

Fixed

  • Map: the world is never drawn more than once. Zoom-out stops where one copy of the world covers the viewport width (log2(width / 256)), "fit" centres world-spanning data at that zoom, and data on both sides of the antimeridian (lon 179 and -179) is framed along the short arc instead of across the globe.
  • The database-type dropdown and the font selects filter as you type (their list delegate was a plain Vec, which ignores the query); typing "sq" lists only SQLite.
  • Results, plans, map features, status and grid edits belong to the console that produced them. Each console has its own results grid (staged edits, sort and scroll survive switching tabs), an EXPLAIN or an edit-apply that finishes while another tab is active is stored with its console, and a console with a running statement shows "Running…" in its own panel.
  • Helix: ctrl-Home / ctrl-End go to the start / last line in Normal and Select mode (and the document ends in Insert mode).

Known limitations

  • No soft wrap or folding in the editor; the linter is heuristic.
  • Curved geometry types are not decoded.
  • MySQL 8 plan parsing is tested from fixtures only; live testing was against MariaDB 10.11.

  • The map basemap needs network access (cached tiles still draw offline).

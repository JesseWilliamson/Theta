0.1.0-alpha.4

2026-11-11Compare on GitHub

Renamed from Quarry to Theta

The project is now Theta and its icon is the Greek letter θ. The name comes from the theta join (θ-join) of relational algebra, the general form of JOIN. Entries below this one keep the name that was current when they were written. The GitHub repository keeps its old address (JesseWilliamson/Quarry) for now; GitHub redirects it once it is renamed.

Your data carries over:

  • Configuration, history, consoles and the demo database move from <config dir>/quarry/ to <config dir>/theta/ the first time Theta starts, if the new directory does not exist yet (renamed in place, copied if the two are on different filesystems; a notice is printed to stderr). Nothing is overwritten and nothing moves while THETA_CONFIG_DIR is set. The map tile cache moves from <cache dir>/quarry/ to <cache dir>/theta/ the same way.
  • Themes: "Theta Dark" and "Theta Light" are now Theta Dark and Theta Light; a settings.json that names the old ones is read as the new ones, silently (the file is rewritten with the new names the next time settings are saved). The bundled theme file quarry.json is now theta.json.
  • Saved passwords: the keychain service is now theta. A password stored under the old quarry service is read as a fallback and copied to the new one the first time it is needed; the old entry is left in place until the connection is deleted.

What you have to change by hand:

  • Binary and package: quarry is now theta (cargo run -p theta, theta --demo, theta --version prints theta 0.1.0-alpha.4); library crates are theta-core, theta-drivers, theta-sql, theta-geo, theta-editor, theta-editor-view, theta-grid, theta-map-view, theta-plan-view and theta-ui.
  • Environment variables: every QUARRY_* variable is now THETA_* (THETA_CONFIG_DIR, THETA_CACHE_DIR, THETA_WINDOW_SIZE, THETA_DEMO, THETA_TILE_URL_OVERRIDE, and the test and debug switches). The old names are not read any more.
  • Release artifacts: theta-<version>-linux-x86_64.tar.gz, Theta-<version>-linux-x86_64.AppImage, Theta-<version>-macos-<arch>.zip (containing Theta.app) and theta-<version>-windows-x86_64.zip (theta.exe). The Linux install uses theta.desktop, the theta hicolor icon name and ~/.local/bin/theta; uninstall the old quarry files separately.
  • macOS bundle id: dev.quarry.Quarry is now dev.theta.Theta, so macOS treats it as a different app (its preferences and permissions do not carry over).
  • The map tile User-Agent is now Theta/<version> (+<repository url>); the demo stores are "Theta Coffee <City>" (--demo databases created earlier keep the old names).
  • The local test databases keep the legacy name quarry_demo (and the MariaDB user quarry): renaming a live test database would only add churn. Key contexts and element ids moved from Quarry… to Theta…, which matters only to custom keymaps written against the previous alpha.

Changed

  • App icon: the lowercase Greek letter theta, drawn as geometry (a ring with a horizontal bar that overshoots it a little) in thin white lines on the same dark grey gradient tile. The ring is 0.77 as wide as it is tall, the glyph is 54% of the tile height and the stroke 3% of it. The 32/48 px, 24 px and 16 px icons are separate drawings with every edge on a whole pixel (bar on a pixel row, counters at least 2 px at 16 px), and the in-app mark has a heavier stroke. theta-light.svg is the dark-on-light version; everything is regenerated by packaging/icons/build.sh, which now also writes theta-24.svg.
  • The About page and the README explain the name once.

0.1.0-alpha.3

2026-11-11Compare on GitHub

A visual release: a new app icon and a darker text area in Theta Dark. No behaviour changes.

Changed

  • App icon: three stacked isometric slabs drawn as thin white lines on a dark grey gradient (#3b3d42 to #18191b, top-left to bottom-right, with a faint highlight along the top edge). It replaces the "Q" hexagon of 0.1.0-alpha.2 and brings back the stacked blocks of the first icon, now as line art. Three detail levels keep the strokes at least one pixel wide: the full icon for 64 px and up, a simplified one with a heavier stroke and open-topped lower slabs for 32 and 48 px, and a minimal one (top rhombus and two chevrons) for 16 and 24 px. quarry-light.svg is the same drawing in dark lines on a light grey tile, and the glyph on the welcome view is redrawn with a wider gap between slabs so it stays open at about 40 px. Everything is regenerated by packaging/icons/build.sh.
  • Theta Dark: the text area is now the darkest surface, as in Zed. The editor, its gutter, the results grid rows, the plan view, the map panel and the active tab use #21252b (was #282c33); explorer, tab strips, toolbars, column headers and popups stay on the lighter panel colour #2f343e, and the title and status bars one step above that. The active line is a softer lift, dialogs (settings, connection, confirmations) sit on the popup colour so they stand out from the darker editor, and the grid toolbar and footer, the plan toolbar and the messages and history toolbars are now chrome rather than data.
  • Data surfaces share one colour through quarry_ui::data_surface() (the theme's editor background, or its window background when it has none). Themes that define no separate panel colours look as before; Catppuccin Latte's grid and plan now use its lighter editor background.
  • Comments, hints and line numbers are lighter in both Theta themes: comments and hints reach 4:1 contrast and line numbers 3:1 (they were about 2.3:1 and 2:1 in Theta Dark). Theta Light already had the editor as its lightest surface and keeps its surface colours.

Tests

  • A test locks the Theta Dark surface ladder (editor darker than panels, panels darker than the title and status bars) and the contrast minimums for text, muted text, line numbers and comments; a second one covers Theta Light and a third checks that every bundled theme has a readable data surface.

0.1.0-alpha.2

2026-11-11Compare on GitHub

The second pre-release. It adds a Vim keymap to the editor and lets the map show all of a world-wide result. It was run by hand on Linux (X11) like the first one; the macOS and Windows builds are still only compiled and unit-tested in CI.

Added

  • Vim keymap, the third editor key map next to Helix (still the default) and Standard. A modal editor in the Vim tradition (Neovim where they differ): operators (d c y < > = g~ gu gU g? gc), counts, motions, text objects, registers (named, numbered, small delete, "+ "*, ". ": "/), marks and the jumplist, . repeat, macros (q, @), Visual, Visual-line and Visual-block (with block I / A), Replace mode, / ? search with Vim regex and hlsearch, and the ex line (:s :g :normal :sort :m :t :d :y and ranges). space is the leader and opens the same which-key menu as in Helix. About 3,900 engine tests, most of them generated from real Vim 9.1; 137 recorded cases that differ on purpose are listed with their reasons. Tables: docs/KEYBINDINGS.md; scope and deviations (windows, folds, :map, Vimscript, digraphs, gq, tag objects and more are out of scope; options are fixed): the engine README and the user guide.
    • Status bar chip per mode (NORMAL, INSERT, VISUAL, V-LINE, V-BLOCK, REPLACE, each in its own colour), half-typed commands next to it and recording @a while a macro is recorded.
    • The cursor style follows the mode for every key map: block (Normal, Visual, Helix Select), bar (Insert), underline (Vim Replace). Visual-block selections are outlined as one rectangle.
    • Insert mode shares the completion popup rules with Helix (ctrl-n / ctrl-p open it and move in it; the first esc closes the popup and the second leaves Insert mode). = formats the lines it covers; :help opens Settings › Keymap; an unknown :set option says so. H M L and the scroll commands follow what the window shows.
    • The Vim ctrl- letters belong to the editor while it has focus, so mod-w and friends do not reach the application there; see Who wins a key. The ownership test now covers every Vim mode, half-typed commands, the prompt and the popup.
    • The grid, map, plan panel and explorer take their h j k l navigation in the Vim key map too.
  • vim.clipboard_unnamed setting (Settings › Editor › Vim: share the clipboard, default on): yanks and deletes also go to the system clipboard and p pastes what another application copied, like set clipboard=unnamedplus. Off, only "+ and "* use it. Engine option: Editor::set_vim_clipboard_unnamed.
  • Keymap picker. Select Keymap… in the command palette, the gear menu and the View menu replaces Toggle Keymap; Use Helix Keymap, Use Vim Keymap and Use Standard Keymap switch directly. The settings dialog has three buttons, and the keymap reference there follows the active key map as soon as it changes.
  • Welcome view offers the key map as a choice (Helix, Vim, Standard) and shows the key cheat sheet of the one selected.

Changed

  • Map: Fit and zooming out show all the data. The zoom floor was one world width, so in a short, wide panel (1320 × 240, say) world-wide points in the far north and south fell off the top and bottom. The floor is now where the world is 80% as tall as the panel (in a tall, narrow panel the world's width still limits it, so the whole longitude range stays reachable). Where the world is narrower than the panel the basemap repeats sideways with the repeats dimmed, and every feature is drawn exactly once on the copy centred on the camera; hover, click, selection, Show on Map and the measure tool all use that copy.
  • New monochrome app icon: a white "Q" built from an isometric cube outline on a near-black tile, with a heavier variant for 16 and 24 px. The same glyph replaces the stand-in database icon on the welcome view. Every size, the macOS master and quarry.ico are regenerated by packaging/icons/build.sh.

Fixed

  • In the Vim key map ctrl-shift-f, ctrl-shift-e, ctrl-shift-n and ctrl-shift-t were taken for ctrl-f etc. (Vim ignores the case of a ctrl chord), which swallowed Format Document, Focus Explorer, New Connection and Reopen Closed Tab; they now reach the application.
  • Vim = on some lines formatted the whole document; it formats the lines it covers.
  • The welcome view no longer shifts the key map buttons when a shorter key sheet is chosen.

0.1.0-alpha.1

2026-11-11Compare on GitHub

The first release. It is an alpha: the application is complete and wired together, and was run by hand on Linux (X11) against PostgreSQL 16 with PostGIS, MariaDB 10.11 and SQLite. The macOS and Windows builds are compiled and unit-tested in CI but have not been exercised by hand. See Known limitations in the README.

Added

Connections

  • PostgreSQL (PostGIS-aware), MySQL / MariaDB and SQLite connections with TLS modes Disable, Prefer, Require and Verify full.
  • SSH tunnels with key file (optional passphrase), password or ssh-agent authentication; host keys are checked against ~/.ssh/known_hosts (trust on first use, a changed key is refused).
  • Connection dialog with URL paste, Test Connection, Save and Save & Connect; read-only connections; an accent colour per connection; edit, duplicate and delete from the explorer.
  • Passwords in the operating-system keychain, never in connections.json; in memory only when there is no keychain.
  • Automatic reconnect when a statement fails because the session was lost (PostgreSQL class 08 and 57P01/57P02/57P03, MySQL "server has gone away" / "lost connection", broken pipe, EOF): the first failing statement reconnects at once and a plain query outside a transaction is re-run once; anything else is reported as not re-run.
  • Run and Explain on a console whose connection is down connect, wait and then run, and show the connection error in Messages when that fails.
  • Reopen Closed Tab (mod-shift-t, palette, :reopen): the last 20 closed consoles (text, connection, cursor) are kept across restarts, so closing a tab never discards work.
  • --help, --version; --ssh without --ssh-key authenticates with the ssh-agent; unknown flags print the usage and exit with status 2. --demo reuses an existing demo connection.
  • Panics are logged to <config dir>/logs/panic-*.log and shown as a notice with the log path.
  • Command-line flags: --demo, --connect URL (repeatable), --run SQL, --script FILE, --ssh user@host[:port] with --ssh-key PATH, --theme NAME, --stress-catalog[=N], --version, --help; QUARRY_DEMO=1.
  • A demo database (--demo): customers, orders, products, stores, delivery zones and routes in SQLite.

Key handling

  • While the SQL editor has focus its engine's keys win over application shortcuts, derived from the engine itself and tested for both key maps and every mode: Helix Insert ctrl-w deletes a word instead of closing the tab, ctrl-k kills to the end of the line, ctrl-b pages up, ctrl-o is the jumplist, ctrl-n / ctrl-p move the completion selection, and F5 runs all. Refresh Schema is F5 in the explorer and mod-alt-r everywhere. The editor publishes keymap, mode, prompt and completion as key context.
  • The results grid keeps its own chords (mod-0 set NULL, mod-enter, ...), the explorer and pickers keep ctrl-n / ctrl-p.
  • The editor scrolls horizontally to the caret after every edit, including typing at the end of a long line and text from the input method.
  • Messages hide a meaningless error code (SQLite's "Unknown"); Cancel Query, Commit Transaction and Roll Back Transaction are named the same in menus, palette, tooltips and docs.

Connection dialog

  • The database type is a dropdown (icon and label per type, keyboard navigable) driven by one descriptor per kind in quarry-core: label, icon, default port, URL schemes and which form sections apply. Adding a database kind needs no dialog change.

Map

  • Basemap registry and picker (toolbar menu, Settings › Map): OpenStreetMap Standard (default), OpenTopoMap, None (graticule) and user-defined basemaps with {s} and {r} support, per-basemap attribution, max zoom (overzoom beyond it), dark flag and tile cache. The old map_tile_url setting is migrated. CARTO basemaps are not built in: their 2026 terms require an API key (see the user guide).
  • A quieter scale bar (1px rule, end ticks, haloed label) in the bottom-right corner above the attribution.
  • Hover cards, the context menu and the layers popover, and the plan flame-graph card, are drawn on the window overlay layer and clamped to the window, so a short bottom panel no longer clips them. Focus rings of switches in the connection and settings dialogs are no longer cut off at the edge of the scroll area.

Explorer

  • Connections, schemas, tables, views, routines, sequences, columns, keys, foreign keys and indexes, with row estimates, a filter box and keyboard navigation.
  • Foreign keys inferred from column names, shown as Suggested with a confidence, and a Related Tables… picker that lists declared and suggested keys and opens a JOIN query.
  • Table context menu: Open Table, Copy Name, Copy Qualified Name, Generate SELECT / INSERT / UPDATE / DELETE, Show DDL.

Editor

  • A modal Helix key map (counts, registers, macros, text objects, surround, multiple selections, regex selections, : command line, a which-key box for the space menu) and a Standard key map with Zed's default bindings.
  • Context-aware completion for keywords, schemas, tables, columns, aliases, functions and snippets, with JOIN … ON … suggestions from declared and inferred foreign keys; auto-trigger after FROM, JOIN, ON, INTO, UPDATE, TABLE; Enter inserts a newline unless a suggestion was chosen.
  • SQL formatter (indent width and keyword case are settings) and a diagnostics pass for syntax problems, UPDATE/DELETE without WHERE and unknown names. A failed statement is underlined at the server's error position.
  • Hand-written SQL highlighter that copes with half-typed statements.
  • Tabbed consoles that persist across restarts (text, cursor, title, connection, tab order), drag to reorder, Open SQL File… and Save Console As….
  • Editor and results font zoom (mod-=, mod--, mod-0).

Running SQL

  • Run the statement under the cursor, the selection or the whole script; cancel a running query; one query at a time per connection; each result gets its own tab; a configurable row limit that stops the server.
  • Transactions: Begin Transaction, Commit Transaction and Roll Back Transaction, a TXN open indicator with Commit and Roll Back buttons, and a prompt when closing a console or quitting with a transaction open.
  • Confirmation before UPDATE / DELETE without WHERE and before Explain Analyze of a write.
  • Messages tab with per-statement outcomes, notices and errors (code, detail, hint); History tab with search, up to 5,000 entries.

Results

  • Virtualised results grid: type-aware sorting, filtering, rectangular selection, column resize and auto-fit, a value inspector, copy as TSV / JSON / INSERT.
  • Editable results: stage cell edits, new rows and deletions, review the generated UPDATE / INSERT / DELETE statements, and apply them in one transaction.
  • Export to CSV, TSV, JSON, Markdown or SQL INSERT statements for the whole result or the selection, to a file or the clipboard.
  • Foreign-key columns are marked and can be followed to the referenced row (ctrl-click).

Plans and map

  • Explain and Explain Analyze for PostgreSQL, MySQL/MariaDB and SQLite as a tree table, a flame graph and the raw output, with insights (sequential scans, bad row estimates, nested-loop rescans, spills, cartesian products, MySQL filesort and temporary tables, SQLite full scans) and suggested CREATE INDEX statements that open in a console.
  • Map for geometry columns (WKB, EWKB, WKT, GeoJSON; WGS 84, Web-Mercator, UTM) on an OpenStreetMap basemap with an on-disk tile cache, or on a planar grid; layers, feature picking, measure tool, copy coordinates, GeoJSON export, and selection shared with the grid.

Look and feel

  • 38 bundled themes (Theta Dark, Theta Light and 36 from 21 gpui-kit theme files), follow-the-system appearance, import of Zed theme files, IBM Plex Sans and Lilex fonts.
  • Command palette, table, connection and theme pickers, a settings dialog (Appearance, Editor, Data, Map, Keymap, About) and a tolerant hand-editable settings.json.

Libraries

  • quarry-core (the shared contract), quarry-drivers, quarry-sql, quarry-geo, quarry-editor as pure Rust crates; quarry-ui, quarry-editor-view, quarry-grid, quarry-plan-view and quarry-map-view as GPUI crates, each with a stand-alone demo.

Packaging and docs

  • Application icon; Linux tarball with install.sh and an AppImage; macOS .app bundle (ad-hoc signed, not notarised); Windows zip with an embedded icon (unsigned); SHA256SUMS; a release workflow that creates a draft GitHub release, with a dry-run mode.
  • Pre-release versions: 0.1.0-alpha.1 is used verbatim for artifact names, --version and the User-Agent; macOS bundle versions and Windows version resources use the numeric 0.1.0. Re-running the release workflow for a tag replaces an existing draft release.
  • README, user guide, key binding reference, architecture and development guides, contributing guide and a generated third-party licence list.

Fixed

  • Map: the world is never drawn more than once. Zoom-out stops where one copy of the world covers the viewport width (log2(width / 256)), "fit" centres world-spanning data at that zoom, and data on both sides of the antimeridian (lon 179 and -179) is framed along the short arc instead of across the globe.
  • The database-type dropdown and the font selects filter as you type (their list delegate was a plain Vec, which ignores the query); typing "sq" lists only SQLite.
  • Results, plans, map features, status and grid edits belong to the console that produced them. Each console has its own results grid (staged edits, sort and scroll survive switching tabs), an EXPLAIN or an edit-apply that finishes while another tab is active is stored with its console, and a console with a running statement shows "Running…" in its own panel.
  • Helix: ctrl-Home / ctrl-End go to the start / last line in Normal and Select mode (and the document ends in Insert mode).
  • Enter in a confirmation dialog (for example "Apply changes?") confirms its primary choice instead of silently closing it.
  • Secondary (muted) text is pulled toward the foreground when a theme leaves it below 4:1 contrast.

Known limitations

  • No soft wrap or folding in the editor; the linter is heuristic.
  • Curved geometry types are not decoded.
  • MySQL 8 plan parsing is tested from fixtures only; live testing was against MariaDB 10.11.
  • Without a keychain (a bare Linux session) passwords are not persisted.
  • The macOS app is not notarised and the Windows build is unsigned. Neither platform has been exercised by hand.
  • The AppImage does not bundle the Vulkan or Wayland libraries.
  • The map basemap needs network access (cached tiles still draw offline).
